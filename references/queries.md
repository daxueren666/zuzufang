# 检索策略正本（动态搜索词 + 时间窗与排序 + 评论优先）

> 本文件是 SKILL.md 一切搜索词选择、时间窗、排序、评论抓取的正本。核心原则：这是租房工具，检索围绕用户提出的租房问题转，不从避坑出发，不预设关键词模板。
> 频控红线（SKILL.md 优先于本文件）：每批每平台 `--limit 20`、每平台 3-5 组词、批间随机间隔 10-30s、同标的同词 7 天缓存复用；正式总量由 run_collect.py 批次编排自动累计（target 默认建议 300，测试 `--target 5`），不再靠人工逐轮凑。

## 1. 动态组合规则（按意图分两栏）

公式：**搜索词 = 小区名 + 场景词**，从用户的问题现场组合。原料来自 SKILL.md「输入预处理」提取的五元组：标的与关注点进查询词，约束（预算/通勤/合租整租/时间窗）不进搜索词、留给过滤层。

场景词库按意图分两栏（这是词库，不是模板，按用户关注点取用）：

| 意图 | 场景词库 | 组合示例 |
|---|---|---|
| 口碑/讨论 A/B/C | 评价视角词：住过 / 体验 / 怎么样 / 值得吗 / 避坑 / 踩坑 / 吐槽 / 后悔吗 / 租金多少钱 | "天通苑 住过""天通苑 避坑""天通苑 怎么样""天通苑 租房体验""天通苑租金多少钱" |
| 找房源 D | 供给侧词：个人转租 / 房东直租 / 无中介 / 急转 / 直租 / 转租 | "天通苑 个人转租""天通苑 房东直租""天通苑 无中介" |

铁律：**"租房"是泛词，禁止单独作场景词**——泛词搜索会混入大量求租帖（发帖人本人在找房，纯噪声）。要用必须带后缀组成词（"租房体验"可以，"租房"不行）。

铁律：**零添加**——搜索词只用用户原话拆出的标的+场景词（+少量通用评价词）。地铁站名/地铁线路（如"16号线"）/户型/合租单间/预算数字等用户没说的限定词禁止擅自加入；效果不佳先换通用场景词补采，仍不佳才**最后**向用户建议加词（建议是兜底不是起手）。

从用户问题提取关注点的方法：**问题里的名词和担忧就是查询词**。用户问题里的具体关注点（二房东/租金/噪音/某中介名）直接进 query；两栏词库是通用补充。问居住体验用"住过/体验"；问推荐用"怎么样"；找直租用"房东直租/个人转租"；问价格用"租金"或"多少钱"。

- 组合示例（口碑）："天通苑 住过""天通苑 怎么样""天通苑 二房东"。组合示例（找房）："天通苑 个人转租""天通苑 房东直租"。
- 中介/房东标的用：`{中介名} 靠谱吗`、`{中介名} 套路`、`{中介名} 退费`（12315 侧传法见下表）。
- 用户没提的角度只补 2-3 个评价视角词（怎么样/住过/体验/小区推荐），禁止铺开维度词矩阵，更不从避坑出发。
- 预算、通勤等条件优先进过滤层（清洗筛选），一般不进搜索词；房源类可加一轮"{小区} {预算} 转租"。

平台传法（词一样，传法不同）：

| 平台 | 传法 |
|---|---|
| 批次编排 run_collect.py | 统一逗号串 `--queries "天通苑 住过,天通苑怎么样,天通苑二房东"` + `--platforms "xhs,douban,web,douyin"`，正式路径首选；豆瓣意图走 `--douban-intent word|listing`（默认 word） |
| 小红书 collect_xhs.py | 单串原样搜索，口语化组合直接可用 |
| 抖音 collect_douyin.py | 词原样传入搜索（如 `--query "天通苑 避坑"`），组合是调用方职责 |
| 豆瓣 collect_douban.py | 口碑（`--intent word`，默认）：评价词直接进 query 裸搜，例 `--query "天通苑 住过"`；找房（`--intent listing`）：默认双拼"转租 直租 合租"，可 `--rental-words "个人转租 房东直租"` 覆盖 |
| web collect_web.py | 整句语义搜索更好（"在天通苑租房是什么体验"），可加 site: 定向贴吧/知乎 |
| 12315 collect_12315.py（仅中介/房东） | `{中介名}`、`{中介名} 退费`（不进编排器，单独跑） |

**与 run_collect 的衔接**：按上面规则现场生成的 3-5 组词，直接拼成逗号分隔串传给 `--queries`（五元组的标的+关注点进词、约束留给过滤层，原则不变）；词不够用或词尽未达量时由 `--extra-queries` 补位。轻量场景（意图 C 等小量采集）才直跑单脚本，按上表平台传法。

标的词形：口语里少有人说全名，用去后缀短名（"天通苑小区"传"天通苑"）；命中过泛或 0 命中，再加回后缀或城市词收窄；同名小区多城时首轮带城市词。平台词形差异见下节「平台词形差异」。

## 1.5 平台词形差异

同一搜索词在不同平台要变形，本节是词形差异正本：

1. **豆瓣 = 裸标的词**。实测豆瓣 cat=1013 搜索对组合词会丢标的词：q="回龙观 租房"返回 40 条全站泛租房帖 0 命中回龙观，q="回龙观"裸词 28 条 13 命中正常。所以豆瓣的 query 只传标的词本身（如 `--query "回龙观"`），不拼场景词；帖子的实体过滤交给 title_relevant AND 语义与清洗层兜底。collect_douban.py 已内置自愈：组合词 0 命中自动降级首词重搜一次（自动跳过"北京"等城市词），无需人工换词，但正路仍是传裸词。
2. **小区级标的在 xhs/web/douyin 建议加城市前缀**（如"北京 龙泽苑"）。实测不加前缀会混入外地同名小区帖（龙泽苑混入绍兴/宜兴/晋城同名帖 6+/13）；豆瓣因小组本身有城市属性可不用。
3. **词效实测结论**：评价词信号密度"避坑" > "体验" > "吐槽"，多词场景优先前两者（"吐槽"帖多为情绪宣泄，可采信号密度低）。

## 2. 排序组合矩阵（时间窗 × 排序）

本节为排序组合正本（SKILL.md「排序组合矩阵」仅存铁律摘要并指向此处）。排序键三种：`discussion`（评论最多）、`hot`（点赞最热）、`time`（发布时间最新在前），可逗号组合成多队列，两条队列都爬。**只有意图 D 用 time + 近 7 天；A/B/C 一律 discussion,hot 双队列 + 近 180 天**。

| 场景 | 意图 | 时间窗 | 排序 | 脚本参数 |
|---|---|---|---|---|
| 口碑/讨论类 | A/B/C 一律 | 近 180 天 | discussion+hot 双队列（评论最多与点赞最热都爬，讨论最重要） | `--days 180 --sort discussion,hot` |
| 找房源 | D | 最近 7 天 | 发布时间，最新在前 | `--days 7 --sort time` |
| 争议热点 | 近期风波/舆情发酵 | 近 7 天 | discussion+hot 双队列 | `--days 7 --sort discussion,hot` |

- 用户明确指定时间范围或排序口径时按用户的组合传参（例："最近一个月讨论最多的" → `--days 30 --sort discussion`；"最近一周的新房源" → `--days 7 --sort time`）。
- 意图 D 超过 7 天的转租帖基本失效，采到也只作参考，报告里必须标注发布时间。
- 选证据的优先级与排序键一致：讨论类先看高评论数帖，房源类先看最新帖。

## 3. 评论优先原则

帖子的价值一半在评论区：楼主的补充、同小区邻居的回应、佐证与反驳都在评论里，真实讨论比帖子本身更可信。二房东、噪音、押金这类话题的核心证据往往就藏在评论区。

- 评论必抓：`--top-comments`（正式 20、测试 5），按最热排序取。
- 评论区高价值信号："我也住""我就在X区/X楼""同小区""补充""去年搬走""住了X年""是真的""假的/骗人"。出现"我也住/同小区/补充"的评论按独立住户样本对待，可单独进 evidence。
- 时间线索：评论时间能判断帖子是否过时，房源帖评论区"还在吗"的提问时间可反推真实有效期。
- 评论与正文矛盾是重要线索而非噪音，两边各引一条进证据链，等第三源印证。

## 4. 完整示例

例 1：用户问"天通苑租房有什么推荐"（意图 A/B，讨论类）
- 提取：小区名=天通苑；"推荐"是主关注点→评价视角词；补"住过/怎么样"。
- 生成词：天通苑怎么样 / 天通苑住过 / 天通苑租房体验（3-5 组以内，"租房"不单独用）。
- 编排：`python <skill>/scripts/run_collect.py --target 300 --queries "天通苑怎么样,天通苑住过,天通苑租房体验" --platforms "xhs,douban,web,douyin" --days 180 --sort "discussion,hot" --min-per-platform 20`，评论按最热取 top（正式 20）；豆瓣默认 word 意图（裸搜防求租帖）。
- 分析首要任务：给推荐结论（verdict + 适合人群）。

例 2：用户问"预算3000，天通苑有房东直租吗"（意图 D，找房源）
- 提取：小区名=天通苑；场景词=房东直租、个人转租（供给侧）；预算 3000 进过滤层不进搜索词（可加一轮"天通苑 3000 转租"）。
- 生成词：天通苑个人转租 / 天通苑房东直租 / 天通苑无中介。
- 编排：`python <skill>/scripts/run_collect.py --target 60 --queries "天通苑个人转租,天通苑房东直租,天通苑无中介" --platforms "douban,xhs" --days 7 --sort "time" --douban-intent listing --min-per-platform 10`，按发布时间最新在前，豆瓣为主源（租房小组，listing 意图双拼供给侧词）。
- 分析首要任务：汇总在租房源列表，预算筛后展示。

例 3：用户问"天通苑二房东多吗"（意图 A，口碑讨论）
- 提取：小区名=天通苑；关注点=二房东（用户问题原词直接进 query）；补评价词"住过/避坑"。
- 生成词：天通苑二房东 / 天通苑住过 / 天通苑避坑。
- 参数：`--days 180 --sort discussion,hot` 双队列（讨论最重要），二房东话题的核心证据在评论区。
- 分析首要任务：给"二房东多不多、怎么识别规避"的结论与证据。
