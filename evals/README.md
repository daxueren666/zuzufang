# evals 目录说明

本目录是 rent-assist 的触发与路由测试集，纯静态文档，不依赖脚本环境，不采集任何数据。

文件清单：
- trigger-tests.md：30 条触发用例。正例 25 条（中文口语，五意图 A/B/C/D/E 各 5 条，含口语化、啰嗦长句、错别字、无标点连打、混合意图拆分），负例 5 条（买房投资/酒店民宿/二手房出售/装修/搬家物流，验证 description 边界）。全部保留人工测试（方法一），不做自动化。
- intent-routing-tests.md：18 条输入预处理与路由用例（R01-R18，180 分制），分五组：啰嗦提问五元组提取（R01-R05）、超大片区（R06 整体问法不下钻/R07-R08）、复合问题拆分顺序（R09-R11）、模糊输入反问澄清与复述确认（R12-R15）、通勤/噪音闸门回归（R16-R17）、地名直达 A 与零假设/零添加（R18）。是全部用例的权威原文与考点出处。
- evals.json：skill-creator 标准格式的自动化用例集，18 条与 intent-routing-tests.md 的 R01-R18 一一对应（prompt 用用户原话，expectations 为可验证断言：路由字母/拆分顺序/澄清动作/闸门开关/关键动作如 collect_12315、不采集等）。
- run_routing_evals.py：路由 desk-check 运行器（纯标准库、不联网、不调 API、不采集）。它用静态规则表分类器复现 SKILL.md 路由口径，逐条断言期望路由、拆分顺序与 R16/R17 闸门行为。

## 方法零：自动化路由 desk-check（run_routing_evals.py）

适用场景：改过 evals.json、路由规则口径或做提交前回归。这是规则表自洽性检查（desk-check 自动化），不是 LLM 评测，测不了模型实际路由质量。

    cd rent-assist && python evals/run_routing_evals.py

全绿退出码 0。跑的是：18 条用例的"路由/动作 5 分"部分；"五元组 5 字段各 1 分"涉及语义提取，保留给方法二人工/LLM 判。

## 180 分制与自动化的映射

- 每条 10 分 = 路由/动作 5 分（可机判，run_routing_evals.py 覆盖，18 条共 90 分）+ 五元组 5 字段各 1 分（人工/LLM 判，90 分）。
- 通过线：总分不低于 144/180，且 R09-R11 拆分顺序、R12-R14 澄清行为、R16/R17 闸门零错误。自动化跑全绿相当于机判部分 85/85 满分，再用方法二补五元组部分（每条 5 分，需 54/90 才够 144）。

## 哪些自动化、哪些人工

- 自动化（evals.json + run_routing_evals.py）：R01-R18 的路由结果、复合拆分顺序（R09-R11）、澄清动作类型（R08/R12/R13/R15）、R14 反问动作、R16 通勤闸门（不答即关闭）、R17 噪音闸门（主动问才开启）。
- 人工（intent-routing-tests.md 保留为权威考点）：五元组逐字段语义提取（含城市推断如"回龙观推北京"）、搜索词具体组合、澄清话术质量、超大片区处理（子区数据归纳）是否到位、报告内容（如"未实地验证"标注）。trigger-tests.md 全部人工，不动。

## 方法一：人工终测触发率

适用场景：改过 SKILL.md 的 description、或发布前的最终验收。步骤：

1. 确认 skill 已安装在 Claude Code 可发现的位置，新开一个会话（或 /clear 清上下文）。
2. 从 trigger-tests.md 逐条复制"用户原话"，原样粘贴发送。注意：不要加"请用租房 skill""帮我查租房"之类的引导词，否则测的是引导词而不是 description 本身。
3. 判断是否触发：会话开始走 rent-assist 的工作流（例如先跑 check_deps.py、或按流程问城市/预算）即算触发；仅泛泛回答、调用其他工具或声称无法处理算未触发。
4. 每条在"结果"列打钩记录，同时记下意图是否与 expected_intent 一致（复合问题看拆分顺序）。
5. 每条用例建议单独新会话，避免上一条的上下文污染下一条的触发判断。
6. 按文件末尾的统计口径算触发率、误触发数、意图正确率，对照通过线。不达标先改 description 再全量回归，不要只重测失败条目。

## 方法二：贴给任意 Claude 会话自评路由

适用场景：改过路由表、五元组规则或片区/拆分逻辑后的快速回归，不需要装 skill、不需要跑脚本。

1. 打开任意一个 Claude 会话（Claude Code 或网页版均可）。
2. 把 SKILL.md 里"输入预处理（意图路由之前）"与"第 1 步：意图路由"两节原文贴给它，再贴上 intent-routing-tests.md 全文。
3. 要求它：只做纸面分类，对每条输出五元组与路由结论，不执行采集、不调脚本、不追问用户。
4. 人工比对输出与 expected，按判定口径打分。
5. 也可以把 trigger-tests.md 的正例部分用同样方式让会话判意图，但触发与否必须用方法一实测，会话自评判不了 description 触发。

## 维护规则

1. 新增意图：当天在 trigger-tests.md 为新意图补至少 5 条用例（口语化/啰嗦长句/错别字/复合拆分各至少 1 条），并在 intent-routing-tests.md 补对应五元组用例；负例集同步考虑是否要加新边界。
2. 修改 description 或路由表：必须重跑对应测试。改 description 重跑 trigger-tests 全量；改路由规则重跑 intent-routing-tests 全量。
3. 错例回归：实际使用中漏触发、误触发或路由跑偏的真实问法，原话加进用例并在考点里标注"回归"，修复后该条必须通过。
4. 正负例同步增长：每新增 5 条正例至少补 1 条新的负例，防止边界只用旧例子验证。
5. 用例必须保持真实口语原话，禁止改写成书面腔；错别字用例保留错别字原文。
6. 本目录只放测试文档，不改动 SKILL.md、references/ 与 scripts/。
